# 8.0 Manage Events and Programs

*Creates and maintains Events, Programs, Program Items, and Event Duties. Derived from the System Design Specification §9. Where this document conflicts with the specification, the specification wins.*

---

## Responsibility

8.0 Manage Events and Programs maintains the event lifecycle. It creates and edits Events, their Programs, the Program Items within each Program, and the ad-hoc Event Duties on individual items.

It is the only configuration process permitted to create an operational record — and only because a Program Item has been explicitly linked to a Service Definition.

**Source:** System Design Specification §9.1.11.

---

## Trigger

Administrator action.

**Source:** System Design Specification §9.2.

---

## The 8.0 footprint

| Direction | Store |
| --- | --- |
| Reads | D9 (Event, Program, ProgramItem, EventDuty); D3 (ServiceDefinition for ProgramItem.ServiceDefID); D4 (Member for EventDuty.AssignedMemberID); D10 (AssignmentStatus for EventDuty.AssignmentStatusID) |
| Writes | D9; D3 (event-sourced ServiceOccurrence rows only) |

**Source:** System Design Specification §9.2.

---

## The 8.0 boundary

8.0 is the sole configuration process permitted to create an operational record. This exception is deliberate and bounded: it applies only when a Program Item is linked to a Service Definition. In that case, 8.0 creates an event-sourced Service Occurrence.

8.0 does not:
- create schedule-sourced occurrences (that is 11.0)
- run the roster engine
- manage the recurring rostering loop
- send notifications
- evaluate fill status

**Source:** System Design Specification §9.0, §9.3.

| Column | Notes |
| --- | --- |
| EventDutyID | Primary key |

## Event-sourced occurrence creation

When a Program Item's ServiceDefID is set — at creation or by later edit — the system creates an event-sourced Service Occurrence directly.

The occurrence carries:

- `EventID` populated
- `ScheduleID` null
- `Date` derived from the Program Item's ScheduledStart
- `StartTime` inherited from the linked Service Definition
- `ServiceTypeID` inherited from the linked Service Definition
- `GeneratedBy = Administrator`
- `CreatedBy` = the administrator who created the Program Item
- `FillStatusID` null
- `ChangedBy` null

This occurrence is entirely outside the Occurrence Materializer. It is not subject to 11.0's idempotency, not covered by the (ScheduleID, Date) uniqueness constraint, and not affected by the Materializer's schedule-change or schedule-deactivation rules.

**Source:** System Design Specification §4, §7 (Event-sourced occurrences), §9.1.11.

---

## Removal of ServiceDefID

If a Program Item's ServiceDefID is removed after an occurrence was created, the occurrence is not automatically deleted. Event-sourced occurrences are governed by 8.0, and cleanup is an administrator action, not a system behavior.

**Source:** System Design Specification §9.1.11.

---

## Lifecycle

Event, Program, ProgramItem, and EventDuty each carry lifecycle state (except Program, which has no IsActive flag in the current specification — it is one-per-event and deactivated only by deactivating its Event).

Events, ProgramItems, and EventDuties are deactivated, never deleted. Deactivation does not cascade. Existing event-sourced occurrences remain.

**Source:** System Design Specification §9.1.1, §9.1.11.

---

## Invariants

- One Program per Event.
- ProgramItem does not store status; it is computed.
- EventDuty references an existing Member directly, with no roster engine run.
- EventDuty.Label is free text, not a Duty reference.
- Event-sourced ServiceOccurrences are created only by 8.0, never by 11.0.
- Event-sourced occurrences have GeneratedBy = Administrator and CreatedBy = the acting admin.
- Deactivation does not cascade and does not touch existing occurrences.
- 8.0 is independent of the recurring roster machinery.
- 8.0 never invokes any other process.

**Source:** System Design Specification §9.3.

---

## What 8.0 does not do

- It does not create schedule-sourced occurrences.
- It does not run the roster engine.
- It does not assign members to configurable duties. Event duties are ad-hoc, not duty-table duties.
- It does not affect the recurring roster loop.
- It does not invoke any other process.

**Source:** System Design Specification §9.2, §9.3.
